Votre cluster est livré avec une observability stack complète, **déjà opérationnelle** : comme le cluster et la gateway, elle fait partie de la plateforme préinstallée. Elle s'adresse à *vous*, l'opérateur, et vous donne des dashboards sur le cluster et sur votre fleet d'agents, sans rien à configurer.

## Les composants

Ils sont fournis par des Operators OpenShift et répartis sur plusieurs namespaces :

- **Grafana** — les dashboards, accessibles à l'adresse **`/grafana`** du site de l'atelier ou par sa Route OpenShift (dans le namespace partagé `monitoring`). Sur un cluster mono-utilisateur, connectez-vous avec `admin` / `openclaw` ; dans un lab partagé, Grafana s'ouvre en lecture seule (rôle Viewer anonyme).
- **Prometheus (via Thanos Querier)** — les metrics du Cluster Monitoring Operator d'OpenShift (namespace `openshift-monitoring`).
- **Alertmanager** — le routage des alertes, fourni lui aussi par le Cluster Monitoring Operator (namespace `openshift-monitoring`).
- **Loki** — l'agrégation des logs, assurée par le Loki Operator (namespace `openshift-logging`).
- **Tempo** — le traçage distribué, assuré par le Tempo Operator (namespace `observability-hub`).
- **OTEL Collector** — l'endpoint de collecte des traces (namespace `observability-hub`).

En résumé, l'**OpenShift Cluster Monitoring Operator** fournit Prometheus (exposé par Thanos Querier) et Alertmanager, le **Loki Operator** l'agrégation des logs et le **Tempo Operator** le traçage distribué, tandis que l'**OTEL Collector** se charge de la collecte des traces. Une instance **Grafana** autonome, dans le namespace `monitoring`, est livrée avec toutes ses sources de données déjà configurées. Un dashboard dédié, **Agent Fleet**, suit le CPU, la mémoire et les redémarrages des pods de vos sandboxes.

## Y accéder

La stack est répartie sur plusieurs namespaces. Vérifiez que les pods sont bien en cours d'exécution :

```bash
oc -n openshift-monitoring get pods
oc -n openshift-logging get pods
oc -n observability-hub get pods
oc -n monitoring get pods
```

<ServiceLink service="grafana">Ouvrez Grafana</ServiceLink> (cluster mono-utilisateur : connectez-vous avec `admin` / `openclaw` ; lab partagé : aucune connexion, accès en lecture seule). Vous arrivez sur le dashboard préchargé **OpenShell Agent Fleet** (CPU, mémoire et redémarrages par sandbox) ; les dashboards Kubernetes standard sont également disponibles. Grafana est servi directement par ce site, à l'adresse **`/grafana`**, au travers d'un proxy de même origine vers le Service Grafana du cluster.

<Callout type="note" title="Déjà déployée (et comment s'en passer)">
Les composants gérés par des Operators (Prometheus, Loki, Tempo, OTEL Collector) sont installés en même temps que la plateforme. L'instance Grafana autonome est installée par les scripts de déploiement, sous la forme d'une release Helm distincte (<code>nemoclaw-monitoring</code>) dans le namespace partagé <code>monitoring</code>.
</Callout>

## Surveiller la fleet

Ouvrez le dashboard **OpenShell Agent Fleet** dans Grafana. Chaque nouvelle sandbox que vous créez (par exemple celles de l'application multi-agents de la partie VI) y apparaît, avec le CPU, la mémoire et les redémarrages de chaque pod d'agent, ainsi que l'état de santé de la gateway elle-même. Dans un lab partagé, choisissez votre namespace (<code><Ns which="openshell" /></code>) dans le sélecteur de namespace du dashboard. Vous disposez ainsi, sur un seul écran, d'une vue d'opérateur sur toute votre fleet d'agents.

<Callout type="note" title="Les agents ont-ils accès à cette télémétrie ?">
Pas par défaut. Une sandbox créée par la gateway est isolée du réseau : elle ne peut joindre que les hôtes autorisés par sa policy. Celle de <code>shifty</code> ne mentionne aucun backend de télémétrie, l'agent ne peut donc interroger ni Prometheus, ni Loki, ni Tempo (la même isolation le tient à l'écart de l'API Kubernetes). Dans la partie VI, vous construirez une <strong>fleet</strong> dont chaque policy autorise exactement <em>un</em> backend (Thanos sur son port tenancy, Loki ou Tempo), avec un token de lecture de courte durée limité à vos propres namespaces. Chaque agent ne voit ainsi que sa part de <em>votre</em> télémétrie.
</Callout>
