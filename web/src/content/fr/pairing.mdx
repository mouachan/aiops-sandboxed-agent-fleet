La première fois que vous ouvrez la Control UI d'OpenClaw dans votre navigateur, elle vous demande d'**appairer l'appareil**, une opération à faire une seule fois. C'est une mesure de sécurité : la gateway ne fait confiance qu'aux navigateurs approuvés par un opérateur de l'hôte. Vous allez procéder comme en conditions réelles, depuis le shell.

<Callout type="note" title="À quoi sert l'appairage">
OpenClaw attribue à chaque navigateur une identité d'appareil (une paire de clés). Un navigateur distant doit être approuvé une première fois par une personne disposant d'un accès opérateur : vous, en exécutant la CLI <strong>dans la sandbox de votre agent</strong> par l'intermédiaire de la gateway OpenShell.
</Callout>

## 1. Se connecter

Ouvrez l'UI OpenClaw (voir la leçon précédente) et connectez-vous avec votre mot de passe. La page affiche alors **« Device pairing required »** : votre navigateur vient d'envoyer une demande d'appairage. Laissez cet onglet ouvert.

## 2. Approuver la demande

```bash
approve-browser
```

La commande approuve la demande en attente la plus récente, c'est-à-dire celle de votre navigateur, et affiche `Approved.` Si elle indique qu'aucune demande n'est en attente, revenez à l'étape 1.

## 3. Recharger la page

Rechargez l'onglet de l'UI OpenClaw : vous êtes connecté.

## Facultatif : ce que fait `approve-browser`

À titre d'information, rien à exécuter : la commande liste les demandes d'appairage (`sbox-openclaw devices list`) puis approuve celle de votre navigateur (`sbox-openclaw devices approve <REQUEST_ID>`). La CLI OpenClaw s'exécute pour cela dans votre sandbox, via la gateway OpenShell.

<Callout type="note" title="« Scope upgrade pending approval » ? Activez d'abord les approbations">
Sur une gateway toute neuve, l'opérateur n'est appairé qu'avec le scope <code>operator.pairing</code> : il peut <em>demander</em> un appairage, mais pas encore <em>approuver</em> qui que ce soit. La commande ci-dessus peut alors échouer avec <strong>« scope upgrade pending approval. »</strong> Il suffit de corriger cela une fois : ouvrez la page <a href="/approvals">Approvals</a> (barre d'outils de l'en-tête) et cliquez sur <strong>Activer les approbations</strong>. L'opérateur reçoit alors le scope admin (et la gateway de l'agent redémarre), ce qui vous permet ensuite d'approuver les appareils normalement. Le provisioning scripté s'en charge à la création de l'agent : ce bouton ne sert que si vous avez créé l'agent à la main ou si vous êtes tombé sur ce deadlock.
</Callout>

## Gérer les appareils

```bash-ref
sbox-openclaw devices remove <DEVICE_ID>   # revoke a device
sbox-openclaw devices clear                # clear all paired devices
```

<Callout type="rh" title="Et en conditions réelles ?">
En production, vous laisseriez l'appairage activé et approuveriez chaque collègue au cas par cas. Sur une machine de workshop jetable, vous pourriez le désactiver (<code>gateway.controlUi.dangerouslyDisableDeviceAuth</code>), mais l'objectif ici est précisément d'apprendre à approuver un appareil.
</Callout>
