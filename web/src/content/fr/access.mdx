<Callout type="rh" title="Votre mot de passe de gateway (nécessaire pour vous connecter)">
L'UI OpenClaw est protégée par un mot de passe. Connectez-vous avec votre mot de passe de gateway : <strong><code>openclaw</code></strong> par défaut sur un cluster mono-utilisateur, un mot de passe aléatoire par participant dans un lab partagé (la valeur de <code>OPENCLAW_GATEWAY_PASSWORD</code>). Affichez le vôtre à tout moment :

```bash
grep OPENCLAW_GATEWAY_PASSWORD ~/workshop/.env
```
</Callout>

La Control UI de votre agent tourne sur le port `30789`, mais **scellée dans la sandbox** : rien à l'extérieur ne peut s'y connecter directement. La sandbox est scellée côté réseau, donc seul `openshell forward` (qui crée un tunnel *à travers* la gateway et le supervisor) peut faire le pont jusqu'à elle.

## Exposez l'UI

**Rien à lancer ici : le pont tourne déjà pour vous.** Le pont, c'est `openshell forward` : il écoute sur un port et fait passer chaque connexion *à travers* la gateway et le supervisor de la sandbox, jusqu'au même port dans la sandbox. Le pod workshop a un **sidecar** `openclaw-forward` qui exécute `openshell forward start 0.0.0.0:30789 shifty` en boucle (il se reconnecte à chaque redémarrage d'OpenClaw), et une Route OpenShift (`openclaw-ui`) pointe vers lui. Votre shell de lab partage le réseau du pod : vérifiez donc le pont directement :

```bash
curl -s -o /dev/null -w "OpenClaw UI: HTTP %{http_code}\n" http://127.0.0.1:30789/
```

`HTTP 200` signifie que le pont est actif : Route → `openshell forward` → gateway → supervisor → l'UI de l'agent.

<Callout type="note" title="Pourquoi un forward et pas un Service ?">
Une <em>sandbox</em> est scellée côté réseau : son pod est cloisonné par une NetworkPolicy, donc rien ne peut se connecter directement à son port d'écoute, pas même un autre pod. Seul <code>openshell forward</code> (qui crée un tunnel <em>à travers</em> la gateway et le supervisor) peut l'atteindre. Un forward par port.
</Callout>

## Ouvrez-la dans votre navigateur

<ServiceLink service="openclaw">Ouvrez l'UI OpenClaw</ServiceLink> (la Route `openclaw-ui` de votre namespace) et connectez-vous avec votre **mot de passe de gateway**. Affichez-le dans votre terminal :

```bash
grep OPENCLAW_GATEWAY_PASSWORD ~/workshop/.env
```

Dans ce lab, c'est un mot de passe aléatoire qui vous est propre (il figure aussi sur la page reçue lors de votre inscription) ; sur un cluster mono-utilisateur, c'est `openclaw`.

Sur le formulaire de connexion d'OpenClaw, laissez **Gateway Token** vide, collez le mot de passe dans le champ **Password**, puis cliquez sur **Connect**. (La gateway utilise l'authentification par mot de passe : un mot de passe saisi dans le champ du token est rejeté avec *Auth required*.)

## Optionnel : le même pont depuis votre propre ordinateur portable

Inutile pour ce lab, et rien à installer pour cela. Plus tard, avec la CLI `openshell` installée sur votre ordinateur portable et connectée à votre propre gateway OpenShell, vous lanceriez le pont vous-même et ouvririez l'UI de l'agent sur `http://localhost:30789` :

```bash-ref
openshell forward start 0.0.0.0:30789 shifty --background
openshell forward list
```

Arrêtez-le avec `openshell forward stop 30789 shifty`.
