When you first open the OpenClaw Control UI from your browser, it asks for **one-time device pairing** — a security feature: the gateway only trusts browsers a host operator has approved. Let's do it the real way, from the shell.

<Callout type="note" title="Why this exists">
OpenClaw gives every browser a device identity (a keypair). A remote browser must be approved once by someone with operator access — that's you, running the CLI <strong>inside your agent's sandbox</strong> via the OpenShell gateway.
</Callout>

## 1. Connect

Open the OpenClaw UI (previous lesson) and log in with your password. The page then shows **“Device pairing required”**: your browser has just sent a pairing request. Leave that tab open.

## 2. Approve it

```bash
approve-browser
```

It approves the newest pending request, which is your browser's, and prints `Approved.` If it says no request is waiting, go back to step 1.

## 3. Reload

Reload the OpenClaw UI tab: you're in.

## Optional: what `approve-browser` does

For information only, nothing to run: it lists the pairing requests (`sbox-openclaw devices list`) and approves your browser's (`sbox-openclaw devices approve <REQUEST_ID>`), with the OpenClaw CLI running inside your sandbox through the OpenShell gateway.

<Callout type="note" title="“Scope upgrade pending approval”? Enable approvals first">
On a brand-new gateway the operator pairs with only the <code>operator.pairing</code> scope — it can <em>request</em> pairing but can't yet <em>approve</em> anyone, so the command above can fail with <strong>“scope upgrade pending approval.”</strong> Fix it once: open the <a href="/approvals">Approvals</a> page (header toolbar) and click <strong>Enable approvals</strong> — it grants the operator the admin scope (and restarts the agent's gateway) so approvals work from here on. The scripted provisioner does this for you at agent creation; you only need the button if you built the agent by hand or hit the deadlock.
</Callout>

## Managing devices

```bash-ref
sbox-openclaw devices remove <DEVICE_ID>   # revoke a device
sbox-openclaw devices clear                # clear all paired devices
```

<Callout type="rh" title="The real-world posture">
In production you'd keep pairing on and approve teammates deliberately. For a throwaway workshop box you could disable it (<code>gateway.controlUi.dangerouslyDisableDeviceAuth</code>), but learning the approve flow is the point here.
</Callout>
